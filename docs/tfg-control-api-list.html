TFG Control Server — API List

Daftar API untuk server kontrol TFG (protokol v2). Senarai ini untuk developer aplikasi mobile jarak jauh.

Base

  • Layanan: tfg-control, API: v1, Protokol: 2.
  • Base path: /v1/.
  • Host: konsol mode klien, atau headless host (tfg-server). Default listen: 127.0.0.1:8787.
  • Client: base URL + Authorization: Bearer <token>.

Autentikasi

  • Token bearer wajib kecuali GET /v1/hello dan POST /v1/pair.
  • Scopes: observe, control_view, admin.
  • observe — baca. control_view — perintah kamera + view.report. admin — pairing & perangkat.

Pairing dan Perangkat

Aplikasi mobile tidak punya scope admin, jadi tidak memanggil POST /v1/pairing. Langkah pertama aplikasi adalah memindai QR yang dibuat operator, lalu menukar code dari QR itu dengan token. POST /v1/pairing hanya dijalankan operator (console / tfg-server).

Alur pairing (mobile)

  1. Memindai QR → baca jawaban pairing. Operator memanggil POST /v1/pairing; server balas JSON berisi code. QR / deep link membawa code + host (url). Aplikasi cukup parsing code dari QR — tidak perlu memanggil /v1/pairing. Contoh jawaban ini dibungkus di dalam QR:
{
  "code": "K7QM-3XPD",
  "expires_in": 120,
  "uri": "tfg-control://pair?url=http://192.168.1.20:8787&code=K7QM-3XPD",
  "payload": "...",
  "url": "http://192.168.1.20:8787",
  "scopes": ["observe", "control_view"]
}

Aplikasi ambil: code ("K7QM-3XPD") dan host dari url (http://192.168.1.20:8787). code berlaku expires_in detik (default 120, dibatasi 30–600).

  1. Tukar code dengan token. Panggil POST /v1/pair — tanpa bearer, karena code itulah kredensialnya — dengan payload di bawah. code dikirim persis seperti yang didapat dari QR.
// POST /v1/pair   (tanpa Authorization header)
// Content-Type: application/json
{ "code": "K7QM-3XPD", "label": "phone" }

Jawaban /v1/pair: simpan token dan pakai sebagai bearer untuk semua panggilan berikutnya. code hanya bisa dipakai sekali; 5 kali salah → 429.

{
  "device": { "id": "dev-4b2379bfa714", "label": "phone", "scopes": ["observe","control_view"], "created_at": 1793084168, "last_seen": 1793084168 },
  "token": "9f2c…",
  "url": "http://192.168.1.20:8787"
}
Ringkas: scan QR → ambil code → POST /v1/pair dengan {code, label} (no auth) → simpan token sebagai Authorization: Bearer <token>. Baru mulai baca (/v1/state, /v1/session) dan kirim perintah.

Keterangan singkat

  • GET /v1/state membawa views, session, readiness, displays — ini yang dibaca client.
  • POST /v1/commands mengirim perintah; jawaban 202 accepted / 200 duplicate.
  • GET /v1/ws menghubungkan realtime: snapshot, camera.changed, session.changed, display.attached, display.rejected, command.accepted, command.rejected.
  • Perintah kamera: camera.nudge, camera.zoom, camera.set, camera.focus; panel: ui.set (crew, scenario, comms).

Langkah Integrasi (dari nol)

  1. Jalankan host kontrol (server atau konsol) di jaringan yang sama; catat host-nya (mis. http://192.168.1.20:8787).
  2. Pairing dulu untuk dapat token. Scan QR dari operator, lalu POST /v1/pair dengan {code, label} (tanpa auth); simpan token sebagai bearer. Detail di Pairing dan Perangkat.
  3. Panggil GET /v1/hello untuk memastikan protokol v2.
  4. Dengan bearer, baca: GET /v1/state, GET /v1/session.
  5. Cek readiness; jika ready, kirim perintah via POST /v1/commands atau buka GET /v1/ws.
  6. Kelola error: 401, 403, 409 not_ready, dst.
